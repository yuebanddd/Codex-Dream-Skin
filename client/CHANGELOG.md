# Changelog

## 0.5.7 — 2026-07-20

- 主题注入先用小型安全探针验证页面直连，页面 WebSocket 无响应时自动改用浏览器级 `Target.attachToTarget` 扁平会话
- 完整主题载荷仅发送到已响应且通过 `app://` 文档校验的 CDP 通道，避免在无响应连接上重复传输大载荷
- 恢复探测上游支持的全部 `app://` 页面，把 `initialRoute` 页面保留为低优先级候选并由实际渲染器探针最终确认
- 成功日志记录页面直连与浏览器附加会话各自完成的目标数，失败日志同时保留两条传输路径的阶段信息
- 版本升级至 0.5.7

## 0.5.6 — 2026-07-20

- Codex 页面连接后直接执行安全探针与主题注入，不再订阅未使用的 Runtime/Page 事件流，避免 Windows 渲染器在 `Runtime.enable` 上阻塞
- 排除带 `initialRoute` 的辅助页面目标，仅向主 Codex 渲染页注入主题
- CDP 命令超时日志增加已接收帧数、事件数与最近事件方法，不记录页面内容
- 版本升级至 0.5.6

## 0.5.5 — 2026-07-19

- Windows release 构建接入可选的 SignPath Foundation Authenticode 双阶段签名：先签主程序，再签 NSIS 安装器
- SignPath 未就绪时采用与 CC Switch 相同的 unsigned 过渡发布方式，并在 Release Notes 与构建元数据明确标记；不声称已获得 Microsoft 云端声誉
- 设置 `SIGNPATH_ENABLED=true` 后强制验证签名链、发布者和可信时间戳；配置缺失或验证失败时停止发布，不回退到未签名安装包
- PR 与手动构建保持无签名，避免不受信任的变更接触签名凭据；发布元数据严格区分实际签名状态
- 新增 MIT 根许可证、隐私政策、安全报告说明、代码签名政策与 SignPath 申请配置指南
- 为签名工作流、发布元数据检查和信任政策增加明确的 CODEOWNERS 审核边界
- 版本升级至 0.5.5

## 0.5.4 — 2026-07-18

- Windows Store/MSIX 版 Codex 改用 Rust 原生 `IApplicationActivationManager` 启动，不再直接执行受保护的 `WindowsApps` 可执行文件
- 从已验证 Store 包的 Package Family Name 与应用清单 ID 构造 AUMID，并将 CDP 参数交给系统应用激活器
- 主题启动和恢复原生启动统一走无控制台窗口的 Store 激活路径，避免黑框与 `os error 5` 权限错误
- 启动日志记录激活方式与 AUMID，便于确认实机是否进入原生 MSIX 激活流程
- 保留系统激活返回的进程 PID，并以该 PID 的进程树和已验证 Store 包根目录共同校验 CDP 监听者；兼容包内实际运行的 `codex.exe`
- 版本升级至 0.5.4

## 0.5.3 — 2026-07-17

- 渲染页安全校验不再依赖 Codex 私有 class 名，改用官方进程、监听者、浏览器身份、`app://` 目标与页面就绪状态的分层验证
- Rust 内置主题适配器同时维护 v1 订阅 CSS 使用的根类、背景变量、明暗模式、主页标记和装饰层 DOM，无需旧版脚本
- 应用与 watcher 只有在样式节点、根类、背景变量和主题所需装饰层均可观测时才确认主题运行成功
- 诊断快照改为逐目标限时并保留部分结果，单个 CDP 页面超时不再丢失整个现场
- 版本升级至 0.5.3

## 0.5.2 — 2026-07-17

- CDP 就绪、恢复、重注入和 watcher 失败时自动把安全的目标与 DOM 结构指纹写入滚动日志，无需手动导出诊断 JSON
- 诊断指纹限制目标、元素与字符串数量，不采集页面文本、标题、表单值、查询参数或浏览器存储
- GitHub Release 安装包改为包含版本、平台和架构的直观文件名，并在 Release 正文列出下载说明
- 停止构建 macOS Intel/x64 安装包，发布矩阵仅保留 macOS arm64 与 Windows x64
- 仓库首页新增固定的 Releases 下载入口和平台文件名对照
- 版本升级至 0.5.2

## 0.5.1 — 2026-07-17

- Windows 渲染页在每次连接后先启用 Runtime 与 Page 域，再在同一 CDP 会话内完成 DOM 校验与主题注入
- Windows 启动 Codex 与内部系统检查统一使用隐藏进程，不再弹出 PowerShell/控制台黑窗
- `Runtime.evaluate` 使用独立 30 秒时限，错误包含命令、目标 ID 与载荷大小
- 新增 1 MiB 滚动 JSONL 运行日志，Unix 权限固定为 `0600`，诊断页直接展示日志路径
- PR 阶段汇总并复验三个平台的发布资产，合并到 `release` 后才自动创建唯一版本号的 Pre-release
- GitHub Actions 不使用 npm 依赖缓存
- 版本升级至 0.5.1

## 0.5.0 — 2026-07-17

- 新增 macOS arm64/x64 DMG 与 Windows x64 NSIS 测试安装包工作流
- 每个安装包产物附带 `BUILD-INFO.json` 和 `SHA256SUMS.txt`
- 构建元数据记录版本、提交、平台、架构、大小与 SHA-256
- 新增跨 package、Tauri 与 Cargo 配置的版本一致性检查
- 客户端诊断信息增加构建提交，并支持显式导出 JSON
- 测试安装包保持无签名，不自动创建 GitHub Release
- 版本升级至 0.5.0

## 0.4.0 — 2026-07-17

- 新增不退出 Codex 的皮肤暂停与恢复，暂停状态跨 LumaDrobe 重启持久化
- 暂停时等待自动重注入 watcher 完整退出后再移除主题，避免并发重注入
- 恢复皮肤失败时回滚到持久化暂停状态，避免产生无人管理的注入会话
- 新增只读运行诊断页，检查官方安装、进程、监听身份、CDP 会话和 Codex 渲染页
- 诊断信息展示客户端与 Codex 版本、平台架构、会话记录和可执行文件路径
- 暂停中的主题继续受到更新与删除保护
- 版本升级至 0.4.0

## 0.3.0 — 2026-07-16

- 新增 Rust Codex 发现服务，校验 macOS Bundle ID、代码签名团队与 Windows Store 包身份
- 新增严格回环 CDP 客户端，拒绝非 loopback、错端口、带凭据或异常路径的 WebSocket URL
- 启动前验证 CDP 监听进程属于官方 Codex，并以浏览器 ID 锚定会话身份
- 仅向通过 `app://` 与 Codex DOM 标记双重验证的渲染页注入主题
- 从已安装主题生成内置 Renderer Payload，不允许订阅源提供 JavaScript
- 注入前重新校验本地图片和 CSS 的路径、体积与 SHA-256，拒绝安装后篡改
- 新增“应用并启动”、会话内热切换、Renderer 重载自动重注入
- 新增运行状态持久化与客户端重启恢复监护
- 新增“恢复原生并重启”，先验证保存的应用、端口与浏览器身份再操作进程
- 运行中的主题不可删除，避免本地状态与活动会话分叉
- 版本升级至 0.3.0

## 0.2.0 — 2026-07-16

- 产品正式命名为 LumaDrobe，并完成桌面应用、包名和界面品牌替换
- 新增 Rust 本地主题安装服务和持久化安装目录
- 对图片进行体积与文件签名校验，仅接受 PNG、JPEG 和 WebP
- 对 CSS 进行 UTF-8、体积、远程资源、`@import` 和危险协议检查
- 为每个落盘资源记录 SHA-256，安装过程先写临时目录再切换
- 新增安装状态、下载并安装、更新清理和安全删除界面交互
- 已安装主题可在取消订阅后继续离线显示
- 拒绝 `.` 与 `..` 作为订阅源、主题或版本的存储路径组件
- 按主题版本区分“已安装”和“可更新”，允许安全升级到新版本
- 解码 CSS 转义后再执行安全检查，阻止转义形式的远程导入
- 已安装主题优先使用本地资源，保持订阅时也可离线预览
- Windows 使用可覆盖目标的原子文件替换，确保重复安装和删除可持久化
- CSS 安全检查同时归一化注释与 `url()` 空白，阻止协议相对远程资源
- 逐块读取主题资源并在超限时立即中止，避免无长度响应导致过量内存占用
- 阻止所有 `file:` URL 形式访问本地文件
- 版本升级至 0.2.0
